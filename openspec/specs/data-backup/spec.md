# data-backup Specification

## Purpose

Ручной перенос данных приложения: экспорт и импорт JSON с предпросмотром и безопасными стратегиями, страховочный бэкап перед заменой и выгрузка журнала в CSV для анализа.

## Requirements

### Requirement: Экспорт JSON

Пользователь SHALL иметь возможность сохранить все данные в JSON-файл через системный диалог. Файл SHALL содержать `schemaVersion`, версию приложения, дату экспорта, настройки, `trainerSettings`, все упражнения (включая архивные) и все записи журнала. `clientId` упражнений и записей SHALL сохраняться, а `exerciseClientId` SHALL связывать запись с упражнением.

#### Scenario: Полный экспорт

- **WHEN** пользователь выбирает «Экспорт JSON» и подтверждает имя файла
- **THEN** создаётся JSON-файл со всеми упражнениями и записями, а пользователь видит сообщение об успехе

#### Scenario: Архивные упражнения попадают в файл

- **WHEN** в справочнике есть архивное упражнение со связанными записями
- **THEN** упражнение и его записи присутствуют в JSON с признаком архива

#### Scenario: «Сиротские» записи сохраняются

- **WHEN** у записи нет связанного упражнения
- **THEN** она экспортируется с `exerciseClientId = null` и сохранённым `exerciseName`

#### Scenario: Отмена сохранения

- **WHEN** пользователь закрывает системный диалог сохранения без выбора файла
- **THEN** экспорт не выполняется и данные не меняются

### Requirement: Защита от секретов

JSON-файл MUST NOT содержать API-ключи, токены и другие секреты приложения. Экспортируются только пользовательские данные и настройки.

#### Scenario: API-ключ не попадает в файл

- **WHEN** пользователь экспортирует JSON
- **THEN** в файле нет `OPENROUTER_API_KEY` и других секретов

### Requirement: Валидация импорта

Перед применением импорта система SHALL проверить JSON и `schemaVersion`. Файл с версией новее поддерживаемой MUST быть отклонён с сообщением об обновлении приложения. Повреждённый JSON MUST быть отклонён, а база MUST остаться неизменной.

#### Scenario: Повреждённый JSON

- **WHEN** пользователь выбирает файл с некорректным JSON
- **THEN** показывается понятная ошибка, импорт не начинается, данные не меняются

#### Scenario: Слишком новая версия схемы

- **WHEN** `schemaVersion` файла больше поддерживаемой
- **THEN** импорт отклоняется с предложением обновить приложение

#### Scenario: Неподдерживаемый формат

- **WHEN** файл не содержит обязательных полей `schemaVersion` или `exercises`/`entries`
- **THEN** импорт отклоняется с сообщением об ошибке

### Requirement: Предпросмотр импорта

До записи система SHALL показать предпросмотр: количество записей и упражнений в файле, текущие количества, для объединения — сколько добавится и сколько совпадёт, для замены — сколько будет удалено. Предпросмотр MUST NOT изменять данные.

#### Scenario: Предпросмотр объединения

- **WHEN** пользователь выбирает валидный файл
- **THEN** показываются количества файла и текущей базы, а также ожидаемые добавления и совпадения

#### Scenario: Предпросмотр замены

- **WHEN** пользователь рассматривает стратегию «Заменить всё»
- **THEN** показывается, сколько текущих записей и упражнений будет удалено

#### Scenario: Отмена после предпросмотра

- **WHEN** пользователь закрывает предпросмотр
- **THEN** импорт не выполняется, данные не меняются

### Requirement: Объединение данных

Стратегия «Объединить» SHALL сохранять все существующие данные и добавлять отсутствующие. Упражнения SHALL сопоставляться по `clientId`, затем по нормализованному имени; записи — по `clientId`, затем по натуральному ключу `(exerciseClientId, date, weight, reps)`. Дубликаты MUST NOT создаваться, операция SHALL быть атомарной.

#### Scenario: Импорт в непустую базу

- **WHEN** пользователь импортирует файл в базу с данными
- **THEN** количество записей и упражнений не уменьшается, новые данные добавляются

#### Scenario: Совпадение упражнения по clientId

- **WHEN** упражнение из файла уже есть по `clientId`
- **THEN** его поля обновляются, дубликат не создаётся

#### Scenario: Совпадение упражнения по имени

- **WHEN** упражнение из файла совпадает с локальным по нормализованному имени, но имеет другой `clientId`
- **THEN** запись связывается с локальным упражнением, локальный `clientId` сохраняется

#### Scenario: Дубликат записи по натуральному ключу

- **WHEN** запись с теми же упражнением, датой, весом и повторами уже существует
- **THEN** новая запись не создаётся

#### Scenario: Архивное упражнение при объединении

- **WHEN** в файле есть архивное упражнение
- **THEN** оно остаётся архивным после импорта

#### Scenario: Ошибка во время объединения

- **WHEN** импорт завершается ошибкой в середине операции
- **THEN** транзакция откатывается, база остаётся в прежнем состоянии

### Requirement: Замена данных

Стратегия «Заменить всё» SHALL создать страховочный JSON-бэкап текущей базы перед изменением, запросить двойное подтверждение и в одной транзакции удалить текущие упражнения и записи, затем загрузить данные файла. Если страховочный бэкап не создан, импорт MUST NOT начинаться.

#### Scenario: Страховочный бэкап создаётся

- **WHEN** пользователь подтверждает «Заменить всё»
- **THEN** сначала создаётся JSON-бэкап текущих данных, и только потом начинается замена

#### Scenario: Двойное подтверждение

- **WHEN** пользователь выбирает «Заменить всё»
- **THEN** система показывает предупреждение об удалении и требует отдельного подтверждения

#### Scenario: Отмена замены

- **WHEN** пользователь отменяет подтверждение
- **THEN** данные не меняются

#### Scenario: Точная замена

- **WHEN** замена завершается успешно
- **THEN** в базе остаются только упражнения и записи из файла в количестве, указанном в предпросмотре

#### Scenario: Ошибка замены

- **WHEN** замена завершается ошибкой
- **THEN** транзакция откатывается, прежние данные сохраняются

#### Scenario: Страховочным бэкапом можно поделиться

- **WHEN** страховочный бэкап создан
- **THEN** пользователь может открыть системный share-диалог для этого файла

### Requirement: Настройки при импорте

Система SHALL применять настройки и `trainerSettings` из файла только при включённой галочке «Также применить настройки из файла». По умолчанию настройки локального устройства MUST оставаться без изменений.

#### Scenario: Галочка выключена

- **WHEN** пользователь импортирует данные с выключенной галочкой
- **THEN** настройки приложения остаются прежними

#### Scenario: Галочка включена

- **WHEN** пользователь импортирует данные с включённой галочкой
- **THEN** настройки и `trainerSettings` применяются из файла

#### Scenario: Некорректное значение настройки

- **WHEN** в файле есть неизвестное значение настройки
- **THEN** это значение игнорируется, текущая настройка сохраняется

### Requirement: Экспорт CSV

Система SHALL экспортировать журнал в CSV: UTF-8 с BOM, разделитель `;`, колонки «Дата; Упражнение; Мышечная группа; Вес; Повторы; Объём». Строки SHALL идти в порядке `date ASC, id ASC`. CSV MUST NOT содержать настройки и `clientId`; импорт CSV не поддерживается.

#### Scenario: Корректный CSV

- **WHEN** пользователь выбирает «Экспорт журнала в CSV»
- **THEN** файл содержит BOM, заголовок и по строке на каждую запись

#### Scenario: Спецсимволы в названии

- **WHEN** название упражнения содержит `;`, кавычки или перевод строки
- **THEN** значение корректно экранируется в CSV

#### Scenario: Порядок строк

- **WHEN** журнал содержит записи за разные даты
- **THEN** в CSV сначала идут более ранние даты, внутри дня — по возрастанию `id`

#### Scenario: Отмена экспорта CSV

- **WHEN** пользователь закрывает диалог сохранения
- **THEN** файл не создаётся

### Requirement: UI резервного копирования

В настройках SHALL быть раздел «Резервное копирование» с кнопками экспорта JSON, импорта JSON и экспорта CSV. Система MUST обрабатывать отмену диалога, ошибки ввода-вывода и отсутствие подходящего приложения через сообщение пользователю, не завершаясь крашем.

#### Scenario: Раздел доступен

- **WHEN** пользователь открывает настройки
- **THEN** он видит раздел «Резервное копирование» с тремя действиями

#### Scenario: Успешный экспорт

- **WHEN** экспорт завершён
- **THEN** показывается сообщение с количеством выгруженных данных

#### Scenario: Ошибка ввода-вывода

- **WHEN** файл не удаётся прочитать или записать
- **THEN** показывается понятное сообщение, приложение продолжает работать

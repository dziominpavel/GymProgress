# membership-reminder

Спецификация capability «Напоминание о сроке абонемента».

Хранение даты окончания абонемента, ежедневная фоновая проверка через WorkManager
и показ уведомления в системном трее за 7 дней до истечения (включая день истечения).
Если дата не указана или уже прошла — система молчит.

## Requirements

### Requirement: Хранение даты окончания абонемента

Система SHALL хранить дату окончания абонемента пользователя в DataStore Preferences как ISO-строку (`LocalDate.toString()`). По умолчанию значение SHALL быть `null` (дата не указана).

#### Scenario: Дата не указана (значение по умолчанию)
- **WHEN** приложение установлено впервые и пользователь не вводил дату
- **THEN** `membershipExpiryDate` Flow emits `null`

#### Scenario: Сохранение даты
- **WHEN** пользователь выбирает дату через DatePicker в настройках
- **THEN** система сохраняет её как ISO-строку в DataStore, и Flow emits соответствующий `LocalDate`

#### Scenario: Очистка даты
- **WHEN** пользователь очищает поле даты в настройках
- **THEN** система удаляет ключ из DataStore, и Flow emits `null`

### Requirement: UI ввода даты в настройках

Система SHALL отображать в `SettingsScreen` блок «Дата окончания абонемента» с возможностью выбора даты через Material 3 `DatePickerDialog`. Система MUST запрещать выбор прошедших дат. Поле SHALL быть пустым по умолчанию.

#### Scenario: Отображение пустого поля
- **WHEN** пользователь открывает настройки, и дата не указана
- **THEN** в блоке «Дата окончания абонемента» отображается пустое/плейсхолдерное значение и подсказка о том, что за 7 дней до окончания придёт напоминание

#### Scenario: Выбор даты через календарь
- **WHEN** пользователь тапает по полю даты
- **THEN** открывается `DatePickerDialog` с возможностью выбора даты

#### Scenario: Запрет прошедших дат
- **WHEN** в открытом `DatePickerDialog` пользователь пытается выбрать дату раньше сегодняшней
- **THEN** система MUST запретить выбор (дата недоступна для тапа или отклоняется при подтверждении)

#### Scenario: Отображение выбранной даты
- **WHEN** пользователь подтвердил выбор даты
- **THEN** в поле отображается отформатированная дата (через `FormatUtils.formatDate`), и значение сохраняется в `SettingsRepository`

#### Scenario: Очистка даты из UI
- **WHEN** пользователь нажимает кнопку очистки рядом с датой
- **THEN** поле становится пустым, и в `SettingsRepository` сохраняется `null`

### Requirement: Планирование ежедневной проверки

Система SHALL планировать ежедневную фоновую проверку через WorkManager (`PeriodicWorkRequest` с интервалом 24 часа), когда дата окончания указана (не `null`). Система SHALL отменять запланированную работу, когда дата очищена. Время первой сработки SHALL быть ~12:00 локального времени (через `initialDelay`).

#### Scenario: Планирование при указании даты
- **WHEN** `membershipExpiryDate` становится не-`null`
- **THEN** система вызывает `WorkManager.enqueueUniquePeriodicWork` с уникальным именем, интервалом 24 часа и `initialDelay` до ближайшего 12:00

#### Scenario: Отмена при очистке даты
- **WHEN** `membershipExpiryDate` становится `null`
- **THEN** система вызывает `WorkManager.cancelUniqueWork` с тем же уникальным именем

#### Scenario: Замена при изменении даты
- **WHEN** `membershipExpiryDate` меняется с одной даты на другую
- **THEN** система вызывает `enqueueUniquePeriodicWork` с `ExistingPeriodicWorkPolicy.REPLACE`, чтобы пересчитать `initialDelay`

#### Scenario: Переживание reboot
- **WHEN** устройство перезагружается
- **THEN** WorkManager автоматически восстанавливает запланированную работу без дополнительных разрешений

### Requirement: Ежедневная проверка и показ уведомления

`MembershipReminderWorker` SHALL при каждой сработке читать актуальное значение `membershipExpiryDate` из `SettingsRepository` и показывать уведомление, если сегодня попадает в окно `[expiry-6 .. expiry]` включительно. Система MUST молчать, если дата не указана или уже прошла.

#### Scenario: Дата не указана
- **WHEN** Worker срабатывает, и `membershipExpiryDate == null`
- **THEN** Worker завершается без показа уведомления

#### Scenario: Дата в окне напоминаний
- **WHEN** Worker срабатывает, и `daysLeft = ChronoUnit.DAYS.between(today, expiry)` находится в диапазоне `0..6` включительно
- **THEN** Worker показывает одно уведомление в канале `membership_reminder` с текстом «Абонемент заканчивается через N дней (D MMMM). Не забудь продлить!»

#### Scenario: День истечения
- **WHEN** `daysLeft == 0` (сегодня — день окончания)
- **THEN** Worker показывает уведомление с текстом «Абонемент заканчивается сегодня (D MMMM). Не забудь продлить!»

#### Scenario: Дата ещё далеко
- **WHEN** `daysLeft >= 7`
- **THEN** Worker завершается без показа уведомления

#### Scenario: Дата прошла
- **WHEN** `daysLeft < 0`
- **THEN** Worker завершается без показа уведомления

### Requirement: Канал уведомлений membership_reminder

Система SHALL создать отдельный `NotificationChannel` с идентификатором `membership_reminder`, `IMPORTANCE_DEFAULT`, со звуком и вибрацией по системным настройкам (не silent), с включённым badge. Канал SHALL быть изолирован от существующего канала `active_workout`.

#### Scenario: Создание канала
- **WHEN** `MembershipReminderWorker` впервые собирается показать уведомление
- **THEN** система создаёт канал `membership_reminder` с `IMPORTANCE_DEFAULT`, если он ещё не существует

#### Scenario: Идемпотентность создания
- **WHEN** Worker срабатывает повторно, и канал уже существует
- **THEN** система не создаёт канал повторно

### Requirement: Тап по уведомлению открывает приложение

Уведомление о напоминании SHALL содержать `PendingIntent`, открывающий `MainActivity` при тапе.

#### Scenario: Тап по уведомлению
- **WHEN** пользователь тапает по уведомлению о абонементе
- **THEN** открывается `MainActivity` (с флагом `FLAG_ACTIVITY_SINGLE_TOP`)

### Requirement: Обработка отсутствия разрешения на уведомления

На Android 13+ система MUST обработать `SecurityException` при показе уведомления, если разрешение `POST_NOTIFICATIONS` не выдано, без краша приложения.

#### Scenario: Разрешение не выдано
- **WHEN** Worker пытается показать уведомление, и `NotificationManagerCompat.notify` бросает `SecurityException`
- **THEN** Worker перехватывает исключение, завершается успешно, и дата остаётся сохранённой для будущих сработок

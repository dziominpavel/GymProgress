# Proposal

## Why

Сейчас запись журнала связана с упражнением только строкой `exerciseName`. Из-за этого удаление упражнения оставляет «висячие» записи, переименование зависит от точного совпадения строки, а имена, различающиеся регистром или пробелами, могут разойтись. Это же мешает будущему экспорту/импорту, которому нужны стабильные идентификаторы, не зависящие от `id` и отображаемого имени.

## What Changes

- Добавить стабильный `clientId` (UUID) упражнениям и записям журнала; заполнить его для существующих строк.
- Добавить `WorkoutEntry.exerciseId` с внешним ключом на `Exercise.id` (`ON DELETE SET NULL`). Существующие записи связать по нормализованному имени; записи без пары оставить с `exerciseId = NULL` и прежним `exerciseName`.
- Добавить `Exercise.isArchived`. Удаление упражнения по умолчанию становится архивированием: архивные упражнения исчезают из выбора для новых записей и из рекомендаций тренера, но остаются в истории и статистике. Добавить восстановление из архива и окончательное удаление.
- Добавить `Exercise.nameKey` — нормализованное имя (trim, схлопывание пробелов, нижний регистр) — и уникальный индекс. Существующие дубликаты объединить в каноническое упражнение с перенаправлением записей.
- Переименование упражнения обновляет `exerciseName` у связанных записей в одной транзакции; `clientId` при переименовании не меняется.
- Добавить в справочник режим «Архив» и действия «В архив», «Восстановить», «Удалить навсегда» с предупреждением о сохранении истории.
- **BREAKING** для схемы Room: версия 6 → 7, явная миграция без destructive fallback. После обновления БД старые версии приложения не смогут её открыть.

## Capabilities

### New Capabilities

- `exercise-catalog`: стабильная идентичность упражнений, уникальность нормализованных имён, архивирование/восстановление, окончательное удаление и переименование без разрыва истории.
- `workout-logging`: связь записей журнала с упражнением по стабильному идентификатору, сохранение истории для архивных и удалённых упражнений, корректная работа со «сиротскими» записями.

## Impact

- **Данные и Room:** `data/Exercise.kt`, `data/WorkoutEntry.kt`, `data/ExerciseDao.kt`, `data/WorkoutDao.kt`, `data/AppDatabase.kt` (MIGRATION_6_7, версия 7), `data/FormatUtils.kt`.
- **ViewModel:** `viewmodel/WorkoutViewModel.kt` — добавление/обновление/удаление упражнений, добавление записей, переименование, архивирование и восстановление.
- **UI:** `ui/screens/ExercisesScreen.kt`, `MainActivity.kt`, `ui/screens/AddEntryDialog.kt`, `ui/screens/EditEntryDialog.kt`, `ui/screens/JournalScreen.kt`, `ui/screens/StatsScreen.kt`, `ui/screens/ActiveWorkoutScreen.kt`, `data/TrainerRecommendationEngine.kt`.
- **Тесты и сборка:** unit-тесты нормализации/слияния дубликатов, `androidTest` с `MigrationTestHelper`, экспорт схемы Room (`exportSchema = true`).
- **Следующий change:** `backup-export-import` будет опираться на `clientId` и `exerciseId`; сам экспорт/импорт в этот change не входит.
- **Совместимость:** миграция затрагивает пользовательские данные; нужен тест на реальном дампе БД версии 6 и ручная проверка на устройстве.

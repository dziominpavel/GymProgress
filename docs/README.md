# Документация GymProgress

Здесь собрана внутренняя документация проекта. Все материалы приведены к фактическому состоянию кода (`app/src/main/java/com/example/gymprogress/...`) на 2026-04-25.

## Файлы

- **`DESIGN_SYSTEM.md`** — дизайн-система IRON CORE: палитра (Volt + Obsidian/Carbon), типографика, токены `Spacing`/`Dimens`/`Shape`, правила использования акцента, чек-лист код-ревью UI.
- **`TRAINING_SCORING_REFERENCE.md`** — reference двух систем оценки тренировок: упрощённой (E1RM по Epley/Brzycki + лестница усилия + бонус за подтверждение) и усложнённой (composite stimulus / E1RM / volume по цели). Описывает общий контракт `ScoringEngine` и краевые случаи.
- **`POTENTIAL_ERRORS_ANALYSIS.md`** — текущий технический долг с приоритетами и ссылками на места в коде. Также фиксирует, что уже решено (для исключения повторных обсуждений).
- **`IMPROVEMENT_PLAN.md`** — общий план улучшений (бэкап/импорт-экспорт, UX, графики, дизайн, навигация, активная тренировка, a11y, техдолг, опциональная облачная синхронизация). Только план, без реализации.

## Принципы документации

- Источник истины — реальный код. Если файл расходится с кодом, обновляется файл.
- Планы и идеи — отдельно от reference-документов: `IMPROVEMENT_PLAN.md` для планов, остальные — описывают текущее состояние.
- При изменениях в коде, влияющих на документацию (миграции БД, новые токены темы, новые системы скоринга, удаление мёртвого кода) — синхронно обновлять соответствующий `.md`.
- Внутри документов вместо файловых путей в стиле «файл такой-то» — указывать пакет и имя класса/функции, чтобы было легко найти `Cmd+Shift+F` / `grep`.

## Связанные правила

- `AGENTS.md` в корне репозитория — общие указания для AI-агента (контекст, приоритеты, стиль, обязательная сортировка списков `date ASC, id ASC`).
- `.cursor/rules/*.mdc` — правила, которые подхватываются автоматически IDE.
